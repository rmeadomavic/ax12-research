# CRSF Protocol Reference

Crossfire (CRSF) is TBS's serial protocol used by Crossfire and adopted by ExpressLRS
for RC control and telemetry. This is a quick reference for AX12 reverse-engineering work.

**Official spec:** https://github.com/tbs-fpv/tbs-crsf-spec
**ELRS implementation:** https://github.com/ExpressLRS/ExpressLRS — `src/lib/CrsfProtocol/`

---

## Addresses

| Address | Name         | Description                     |
|---------|--------------|---------------------------------|
| `0xC8`  | Flight Controller | Betaflight / INAV / ArduPilot |
| `0xEA`  | Radio Transmitter | Handset (e.g. AX12)          |
| `0xEE`  | TX Module    | ELRS TX module                  |
| `0xEC`  | Receiver     | ELRS RX module                  |
| `0x00`  | Broadcast    | All devices                     |

---

## Frame Format

### Broadcast Frame (device-to-device, no routing)

```
[sync] [len] [type] [payload ...] [crc]
```

| Field   | Size    | Description                                       |
|---------|---------|---------------------------------------------------|
| sync    | 1 byte  | Device address (`0xC8`, `0xEA`, etc.)             |
| len     | 1 byte  | Byte count from type through CRC (inclusive)       |
| type    | 1 byte  | Frame type ID                                      |
| payload | N bytes | Type-specific data                                 |
| crc     | 1 byte  | CRC-8/DVB-S2 over bytes from type through payload  |

### Extended Frame (routed, origin/destination addressing)

```
[sync] [len] [type] [dst] [src] [payload ...] [crc]
```

| Field   | Size    | Description                                  |
|---------|---------|----------------------------------------------|
| sync    | 1 byte  | Device address                               |
| len     | 1 byte  | Byte count from type through CRC (inclusive)  |
| type    | 1 byte  | Frame type ID (extended types use `0x28`–`0x32`) |
| dst     | 1 byte  | Destination address                          |
| src     | 1 byte  | Origin address                               |
| payload | N bytes | Type-specific data                           |
| crc     | 1 byte  | CRC-8/DVB-S2 over type through payload       |

## CRC Algorithm

**CRC-8/DVB-S2** — polynomial `0xD5`, init `0x00`, no reflect, no final XOR.

```python
def crc8_dvb_s2(data: bytes) -> int:
    crc = 0x00
    for byte in data:
        crc ^= byte
        for _ in range(8):
            if crc & 0x80:
                crc = ((crc << 1) ^ 0xD5) & 0xFF
            else:
                crc = (crc << 1) & 0xFF
    return crc
```

> **Not the same as UMBUS.** UMBUS uses CRC-8/MAXIM (polynomial `0x31` / reflected `0x8C`).
> See [umbus-protocol.md](umbus-protocol.md) for UMBUS CRC details.

## Key Frame Types

Frame types relevant to ELRS telemetry on the AX12:

| ID     | Name               | Payload | Direction    | Description                          |
|--------|--------------------|---------|--------------|--------------------------------------|
| `0x02` | GPS                | 15      | RX -> TX     | Lat, lon, groundspeed, heading, alt, sats |
| `0x08` | Battery Sensor     | 8       | RX -> TX     | Voltage, current, mAh used, remaining %  |
| `0x14` | Link Statistics    | 10      | TX internal  | RSSI, LQ, SNR, RF mode, TX power    |
| `0x1C` | Link Stats RX      | 4       | RX -> TX     | Receiver-side RSSI and link quality  |
| `0x1D` | Link Stats TX      | 4       | TX internal  | Transmitter-side RSSI and link quality |
| `0x1E` | Attitude           | 6       | RX -> TX     | Pitch, roll, yaw (decidegrees)       |
| `0x21` | Flight Mode        | varies  | RX -> TX     | Null-terminated ASCII mode string    |
| `0x3A` | Radio ID (Handset) | 4       | TX internal  | Handset timing/sync                  |
| `0x16` | RC Channels Packed | 22      | TX -> RX     | 16 channels, 11 bits each            |

## 0x14 LINK_STATISTICS Breakdown (10 bytes)

Primary link health frame. Generated by the TX module, not forwarded over air.

```
Offset  Size  Field                    Unit / Notes
──────  ────  ───────────────────────  ─────────────────────────
  0     1     Uplink RSSI Ant. 1       dBm (negative, stored unsigned)
  1     1     Uplink RSSI Ant. 2       dBm (negative, stored unsigned)
  2     1     Uplink Link Quality      % (0–100)
  3     1     Uplink SNR               dB (signed int8)
  4     1     Active Antenna           0 = ant 1, 1 = ant 2
  5     1     RF Mode                  ELRS rate index
  6     1     Uplink TX Power          index into power table
  7     1     Downlink RSSI            dBm (negative, stored unsigned)
  8     1     Downlink Link Quality    % (0–100)
  9     1     Downlink SNR             dB (signed int8)
```

**RF Mode values (ELRS):** Rate index varies by regulatory domain and ELRS version.
Common mappings: 0=4Hz, 1=25Hz, 2=50Hz, 3=100Hz, 4=150Hz, 5=200Hz, 6=250Hz, 7=500Hz.

**TX Power index:** 0=dynamic, 1=10mW, 2=25mW, 3=50mW, 4=100mW, 5=250mW, 6=500mW, 7=1000mW, 8=2000mW.

## UMBUS Encapsulation

On the AX12, CRSF telemetry arrives inside UMBUS type `0x15` frames. The MCU bridges
ELRS CRSF data into the UMBUS serial link for the Android app.

```
UMBUS 0x15 frame structure:
[0xA6] [type/len] [header 2B] [CRSF payload ...] [UMBUS CRC]

The CRSF payload within 0x15 typically contains:
[0xC8] [crsf_len] [crsf_type] [crsf_data ...] [crsf_crc]
```

The outer frame uses UMBUS sync `0xA6` and CRC-8/MAXIM (init `0x32` for type `0x15`).
The inner CRSF data uses sync `0xC8` and CRC-8/DVB-S2.

See [elrs-telemetry-analysis.md](elrs-telemetry-analysis.md) for decoded examples.
